1. S1 SGK/SBT source receipt, lesson/skill/outcome register and original printed page boundaries. Don't confuse S2 table of contents with an S1 audit.
2. **SGK independently complete** Knowledge + solved D2 examples + per-lesson Core + Practice/Application/Written + **PRIVATE chapter-end Readiness**. Reviewer every affected canonical item/role. Preserve original prior PASS by exact snapshot if unaffected.
3. One canonical `item_id`/answer/solution/attempt history and many role/placement references; Topic Core **does not exist**. SGK and Topic self-sufficient separately.
4. SVG and diagrams need math and actual representation audit, and should be created only when pedagogically needed.
5. NotebookLM: Permanent five THPT v2.0 files ONLY, user-provided original SGK/SBT and real `Temp_` file + same-answer short prompt following `06`. Delta policy `07 v1.1`; avoid rerunning prior PASS unchanged.
6. Never reveal protected Chapter/Topic Readiness stem/answer/rubric in GitHub; never show hint/Tutor/key/correctness before **Final Submit**. No unguarded seen Practice item as fresh mastery evidence.
7. File handoff vs release: this conversation authors and independently reviews academic material only. Another conversation owns website, protected backend, browser/device D6, CI, PR merge/deploy and owner release sign-off. `ACADEMIC_CLEARANCE_FOR_RELEASE=NO` until separate gates are met.
