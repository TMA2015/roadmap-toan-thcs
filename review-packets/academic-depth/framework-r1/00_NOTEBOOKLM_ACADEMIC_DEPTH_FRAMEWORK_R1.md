## 1. Purpose

Self-Learning Math is a self-study platform. The new priority is direct learning quality:

- sufficient and accurate theory;
- clear explanations of why/when/conditions;
- representative worked examples;
- interactive practice that strengthens understanding;
- written problem solving;
- exam-relevant and pedagogically valuable problem types;
- reliable help/remediation when the learner is stuck.

Skill/evidence remains useful as an observation layer, but it must not become the center of the project.

Core product test:

**If Skill Map, Mastery and Readiness were turned off, could a learner still go from “I do not know this yet” to “I can solve representative written problems independently”?**

## 2. Source hierarchy

### S1 — Curriculum authority
Official curriculum, KNTT textbooks/workbooks and relevant official guidance.

Use for:
- Core scope;
- terminology;
- conditions/definitions/theorems;
- grade/topic mapping.

Do not infer exam frequency from S1 unless it explicitly supports such a claim.

### S2 — Pedagogical/reference sources
High-quality exercise books, advanced practice, method books, teacher materials.

Use for:
- problem-type structure;
- method progression;
- canonical/classical examples;
- common errors;
- useful intermediate forms.

S2 does not automatically turn advanced material into Core.

### S3 — Authentic assessment
Traceable semester/final tests, official surveys, recent Hanoi grade-10 entrance exams, selected other localities when useful.

Use for:
- actually observed problem forms;
- direct vs multistep/synthesis structure;
- frequency within the selected corpus;
- exam-style coverage gaps.

Do not call a form “common” from a single exam.

### S4 — Extension/challenge
Specialized/challenge/olympiad material.

Use only for clearly separated extension.

### S5 — Draft-only
AI-generated, forum/community, unclear-provenance secondary material.

Use for ideas/drafts only, not to establish academic authority or frequency claims.

## 3. Three dimensions must remain separate

For every concept/problem type:

1. **Curriculum importance**
   - Core / Core-Support / Entrance10 / THPT-Bridge / Specialized-Challenge.

2. **Observed frequency**
   - based on actual source corpus, with source/year/locality/exam type retained.

3. **Pedagogical value**
   - LOW / MEDIUM / HIGH / CANONICAL.

Do not collapse these into one score.

## 4. Problem type, not question count, is the organizing unit

Normalize questions into problem types.

Near-duplicates include:
- number changes only;
- name/context substitutions with same reasoning;
- unit changes without structural effect;
- same method with reordered data only.

Keep variants when they:
- change recognition cues;
- require a different method choice;
- introduce a condition/boundary case;
- change from direct to contextual;
- expose a different common error;
- require transfer/synthesis.

The site should not copy a large source corpus. It should select/design the minimum useful set of examples/practice/written items for each important type.

## 5. Copyright/reuse boundary

Commercial sources are REFERENCE_ONLY by default:
- analyze structure/method/problem types;
- do not bulk-copy statements/solutions;
- create original equivalent items when needed.

Public/official exam items retain provenance; exact reuse must match permitted use.

For classical/canonical problems with unclear reuse rights:
- preserve the mathematical idea;
- record provenance;
- create original wording/solution if needed.

## 6. Six Academic Depth dimensions

### D1 — Theory Depth
Check:
- all required Core concepts;
- correct definitions/conditions;
- what/why/when/conditions/next use;
- prerequisites;
- misconceptions/boundary cases;
- correct Core vs extension layer;
- no exercise requiring an untaught method.

### D2 — Worked Examples
Possible roles:
- BASE;
- METHOD;
- TRAP/CONTRAST;
- CANONICAL;
- TRANSFER;
- SYNTHESIS.

Examples should explain reasoning and method choice, keep conditions visible and reduce support gradually.

### D3 — Interactive Practice
Purpose:
- immediate feedback;
- recognition/routine fluency;
- error discrimination;
- short application;
- varied repetition.

Preferred path:
**Base → Trap/Contrast → Apply → Transfer where appropriate**

No fixed question count guarantees PASS.

### D4 — Written Problem Solving
Written work is first-class.

Useful roles:
- CORE_BASE;
- CORE_APPLY;
- METHOD_CHOICE;
- CONDITION/TRAP;
- MULTISTEP;
- SYNTHESIS;
- EXAM_STYLE;
- CANONICAL_METHOD;
- PROOF / MODELING / CONSTRUCTION;
- optional CHALLENGE.

Each important written item should include:
- clear statement;
- source/provenance or original note;
- problem type;
- layer;
- prerequisites;
- hints where useful;
- complete solution;
- method-choice explanation;
- common mistakes;
- rubric/step-check;
- remediation path.

### D5 — Exam & Authentic Coverage
For each important type, record:
- observed assessment sources;
- years;
- count within corpus;
- direct/multistep/synthesis role;
- curriculum layer.

Do not equate exam frequency with Core status.

### D6 — Help / Remediation
Learner should have a path when stuck:
1. small hint;
2. method hint;
3. one worked step;
4. full explanation on request;
5. prerequisite remediation;
6. similar easier example when helpful.

AI Tutor may support this but must not be the only place where essential curriculum knowledge exists.

## 7. Audit status and priority

Statuses:
- PASS;
- REVISE;
- MISSING;
- INSUFFICIENT_SOURCE;
- NOT_REVIEWED.

Repair priority:
- P0: blocks self-learning / mathematical correctness / missing prerequisite or Core method;
- P1: materially limits written/exam transfer;
- P2: valuable improvement.

Do not treat unmentioned areas as PASS.

## 8. Topic closure

A topic may become SELF_LEARNING_READY_V1 only when:
- D1–D6 are PASS, except D5 may be NOT_APPLICABLE with justification;
- no unresolved P0;
- no required Core problem type remains unreviewed;
- provenance is recorded.

This is conditional on the reviewed corpus, not permanent completeness.

## 9. Existing audits do not carry PASS automatically

Prior structural/manual audits remain prior evidence only.

Do not infer:
- old structural PASS = depth PASS;
- large Practice Bank = problem-type coverage;
- many written items = written-depth sufficiency;
- current Skill Map coverage = academic completeness.
