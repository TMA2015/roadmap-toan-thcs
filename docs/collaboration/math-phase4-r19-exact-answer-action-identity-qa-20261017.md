# Math Phase 4 R19 — Exact answer-action identity contract (QA only)

**Date:** 2026-10-17 · **Status:** QA CONTRACT CANDIDATE / NO LEARNER CUTOVER

## Why R19 follows R18

R18 PR #504 proved that when the R16 v2 journal commits but the legacy v1 grading callback is interrupted, a read-only examiner can identify the committed journal event without unsafe v1 replay. R17 recovered an unresolved intent using `item_id` + a Boolean `correct`. That lookup does **not** identify which wrong choice was selected or distinguish separate attempts/sessions.

R19 does not change Practice scoring. It formalizes and adversarially tests a **stable identity vocabulary** that a future single-transaction writer must persist along with the journal.

## Proposed canonical action envelope

- `learner_scope`: synthetic QA-only namespace (no real learner identifier)
- `session_id`: one learning-session identity
- `presentation_id`: a persistent identity for **this rendering** of a question, distinct when that same item is presented again
- `action_id`: generated on the first answer selection; reused on a retry, not regenerated by a double-click
- `item_id`: exact canonical question identity
- `source_sha256`: SHA-256 of the exact immutable source version containing the canonical option ID and answer key
- `option_id`: an actual source-locked option identity; not the displayed/shuffled position or translated option text
- `correct`: the result of trusted deterministic grading (not user-submitted independent evidence)

**Submission key** = `QA_R19_` + SHA-256(domain | scope | session ID | presentation ID). It intentionally does **not** include answer or action ID: if a user clicks a different choice or generates a new action token for the same rendered question, a future stored receipt must flag a conflict rather than creating a second canonical attempt.

**Answer fingerprint** = SHA-256(domain | item ID | source SHA | selected canonical option ID | correctness). It distinguishes two wrong choices even if both have `correct:false`.

## Prototype and tests

`scripts/prototypes/math-v2-exact-action-identity-r19.js` is a pure QA-injection-only capture/comparison helper. No IndexedDB, localStorage, network calls, production registration or migration. The Node adversarial regression tests:

1. Same session/presentation/action and option produce the same submission key and fingerprint, including a simulated reload/reconstruction.
2. Two different incorrect options share the same submission key but have distinct answer fingerprints and are **rejected as changed-answer conflict**.
3. A changed action ID within the same presentation is rejected; a new presentation and session receive new keys.
4. Any changed question ID or source SHA is rejected for the old presentation.
5. Only explicitly source-locked option IDs and 64-hex SHA-256 source digests are accepted.
6. R16's current Boolean-only event is explicitly classified `R16_LACKS_EXACT_ACTION_PROVENANCE`, NOT approved for automated replay/cutover.
7. The helper's successful comparison remains `EXACT_CAPTURE_MATCH_BUT_NOT_DURABLE`; a pure function does **not** demonstrate crash recovery.

## Protected boundaries and remaining work

- This proof **does not persist an action envelope**. There is no R19 live capture, no automatic R16 journal write, and no Safari proof.
- A production writer must store action identity and exact option fingerprint **in the same IndexedDB transaction** as intent + event + outbox, with a uniqueness constraint on (scope, session, presentation). A separate metadata database or dual-store replay cannot guarantee atomicity.
- Generate and durably retain `session_id`, `presentation_id`, and first `action_id` before accepting a click; preserve exact source SHA/option ID from reviewed question data. Do not synthesize option IDs from shuffled positions silently.
- Preserve `SOURCE_REPORTED` versus unavailable independent Readiness grades; never grant automatic Readiness from Written self-reports.
- Do not import real PC/phone histories into the synthetic ledger or claim that old v1 totals have been migrated.
- Owner-approved PC/iPad Safari canary, multi-tab concurrency, quota errors, backup coverage, and explicit release decision remain required before a production v2 switch.

**Clearance boundary:** Full public Math CI PASS permits merging this **read-only QA contract** into `main`, not deploying a live identity collector or changing learner scores.
